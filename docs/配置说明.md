# 配置说明

配置文件位置：

```
%APPDATA%\EXILED\Configs\Plugins\deepseek_anticheat\<端口>.yml
```

`<端口>` 是你的服务端端口（默认 `7777`）。
**文件名就是端口号** —— 端口不对，EXILED 会重新生成一份默认的，你改的那个就不生效。

`%APPDATA%` 一般是 `C:\Users\你的用户名\AppData\Roaming`。

> **改完必须重启服务端**，配置只在启动时读一次。
>
> 例外：白名单可以用 `.dsac whitelist` 命令改，那样立即生效并写回文件。

## 一、必做的两件事

### ① 填 API Key

```yaml
api_key: 'sk-你的Key'
```

到 https://platform.deepseek.com 申请。

**不填也能用** —— 只跑本地启发式检测，完全不联网、零成本，只是少一层 AI 复核。

### ② 按自己服务器的情况改 `features`

**这一节不改对会导致误报。** 你的服务器开了下面任何功能，就必须把对应项改成 `true`：

| 你的服务器有 | 改成 true | 不改会误报成 |
|---|---|---|
| 无限体力 / 加速插件 | `infinite_stamina` | 移速异常 |
| 无限子弹 | `infinite_ammo` | 无限弹药 |
| 过场 / 通话需要玩家上下飞 | `cutscene_flight` | 飞天 |
| 自定义传送 / 传送门 | `custom_teleport` | 瞬移 |
| 异常治疗类技能或道具 | `abnormal_heal` | 异常回血 |
| 服务器主动给玩家发物品 | `gives_items` | 刷物品（**会清空玩家背包**）|

```yaml
features:
  infinite_stamina: false
  infinite_ammo: false
  cutscene_flight: false
  custom_teleport: false
  abnormal_heal: false
  gives_items: false

  # 管理员用 NoClip / 上帝模式不算作弊（建议保持 true）
  noclip_for_admins: true
  god_mode_for_admins: true

  # 不想整个关掉，只想放宽一点？用倍率
  speed_tolerance_multiplier: 1        # 移速上限乘以这个数
  vertical_tolerance_multiplier: 1     # 垂直速度上限乘以这个数
  item_spam_tolerance_multiplier: 1    # 刷物品门槛乘以这个数

  # 完全跳过检测的玩家（形如 76561199570869496@steam）
  whitelisted_user_ids: []

  # 完全跳过检测的角色（名字包含即匹配，不区分大小写）
  whitelisted_roles: []
```

**大部分普通服务器，全部保持 `false` 就是对的。**

## 二、AI 复核

```yaml
enable_ai_review: true
api_base_url: 'https://api.deepseek.com'
model: 'deepseek-chat'
use_json_response_format: true
timeout_seconds: 20
max_tokens: 400
```

| 项 | 说明 |
|---|---|
| `enable_ai_review` | 关掉就只跑本地检测 |
| `api_base_url` | 换成走 ai-proxy 的话填 `http://127.0.0.1:8787/v1` |
| `model` | `deepseek-chat`（快、便宜）或 `deepseek-reasoner`（更准、更贵）|
| `use_json_response_format` | 部分本地框架（Ollama 等）不支持，会直接报错，这时改 `false` |
| `timeout_seconds` | 本地模型慢的话调大 |
| `include_player_identity` | 是否把昵称/UserID 发给 AI。默认 `false`（不泄露玩家身份）|

### 调用预算

```yaml
max_api_calls_per_player_per_round: 2     # 每人每局最多复核几次
max_api_calls_per_round: 15               # 全服每局最多几次
cooldown_seconds: 120                     # 同一玩家的复核间隔
```

**这几项是防刷爆余额的关键。** 建议保持默认或更小。

## 三、判定阈值与处置

```yaml
local_score_to_report: 35      # 本地分超过这个才送 AI 复核
verdict_threshold: 80          # AI 嫌疑度超过这个才处置
hard_violation_threshold: 50   # 有硬违规时用这个更低的门槛
action: Ban                    # Alert / Kick / Ban / Kill
```

**`action` 的含义**：

| 值 | 行为 |
|---|---|
| `Alert` | **只通报，什么都不做** ← 建议先用这个跑一段时间 |
| `Kick` | 踢出服务器 |
| `Kill` | 当场处死（不封禁）|
| `Ban` | 走下面的递进阶梯 |

### 递进封禁阶梯

```yaml
use_progressive_bans: true
punishment_ladder:
- kill      # 第 1 次：处死
- kill      # 第 2 次：处死
- 3         # 第 3 次：封 3 天
- 7         # 第 4 次：封 7 天
- 90        # 第 5 次：封 90 天
- 365       # 第 6 次：封 365 天
- perm      # 第 7 次起：永久
```

每一档可以填：

| 写法 | 含义 |
|---|---|
| `kill` / `处死` | 当场处死，不封禁 |
| 数字（如 `7`）| 封 N 天 |
| `perm` / `permanent` / `永久` / `0` | 永久封禁 |

超出阶梯长度就一直用最后一档。

**关掉阶梯**（`use_progressive_bans: false`）就用固定天数：

```yaml
ban_duration_days: 7
```
