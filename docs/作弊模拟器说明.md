# 作弊行为模拟器

用于验证 DeepSeekAntiCheat 检测能力的测试工具。

---

## ⚠️ 先说清楚：这不是作弊器

**它不接触游戏。** 没有自瞄，没有内存写入，没有网络包伪造，没有进程注入，没有 DLL 劫持。

它做的唯一一件事是：**伪造一份「行为统计数据」**（命中率、爆头率、射速、伤害……），然后喂给你反作弊的**真实检测链路**，看判定结果对不对。

**因此它原理上不可能被用来在服务器上作弊。** 它也没有任何绕过反作弊的功能 —— 因为它压根不跟游戏交互。

### 为什么不做真作弊器

真正能用的自瞄/扳机需要逆向客户端、操纵游戏内存。问题是：

1. **它在没装反作弊的服务器上照样能用。** 一个"不绕过反作弊"的自瞄，放到别的服务器上依然是自瞄。
2. **它对测试没有额外价值。** 你要验证的是「检测逻辑能不能认出作弊行为」，不是「游戏能不能被黑」。而模拟器能**精确控制**每个参数（爆头率 92.7%、样本量 5、射速 55/秒），反而测得更全 —— 真作弊器做不到这么精确。
3. **它不可控。** 真作弊器的行为取决于游戏版本、当前武器、你的操作，难以复现；模拟器每次跑结果都一样。

## 两种用法

### 用法 A：离线控制台（不需要游戏）

```
CheatSimulator.exe                              跑全部场景，只做本地评分
CheatSimulator.exe --scenario aimbot            只跑匹配的场景
CheatSimulator.exe --ai --key sk-xxx            把场景真的送 DeepSeek 判定
CheatSimulator.exe --ai --url http://127.0.0.1:11434/v1 --no-json-format
                                                用本地 Ollama 判定
```

输出示例：

```
 场景                   说明                     评分    命中率   爆头率   杀/分    送审
 -----------------------------------------------------------------------------------
 legit_newbie         新手玩家                  0.0    23 %   17 %    0.2     否
 legit_veteran        高玩（高爆头但正常）          0.0    65 %   60 %    1.2     否
 cheat_aimbot         自瞄（aimbot）            73.9    92 %   93 %    6.0     是
 cheat_rapidfire      射速修改                  21.9    30 %   25 %    1.6     是
```

### 用法 B：游戏内命令（在真实服务器上验证）

```
dsac list              列出全部场景
dsac sim <场景id>      本地评分（秒回，不调 AI）
dsac ai  <场景id>      本地评分 + DeepSeek 复核（异步，结果广播给管理员）
dsac stats             列出当前跟踪的真实玩家统计与评分
```

> 需要 RemoteAdmin 权限。

**为什么游戏内版本安全**：模拟场景的 `UserId` 传的是 `null`，处置环节按 UserId 查玩家必然查不到。所以**无论 `action` 配置成什么，模拟测试都不可能踢人封人** —— 这是代码层面的保证，不是配置约束。插件里还有一道显式的 `IsSimulation` 早退。

## 场景清单

| 场景 ID | 类型 | 说明 | 预期 |
|---|---|---|---|
| `legit_newbie` | 正常 | 23% 命中 / 17% 爆头 | 不报 |
| `legit_average` | 正常 | 30% 命中 / 20% 爆头 | 不报 |
| `legit_veteran` | 正常 | 65% 命中 / 60% 爆头的高玩 | 不报 |
| `legit_scp096` | 正常 | 特殊角色造成的天然高数据 | 不报 |
| `edge_low_sample` | 边界 | 只有 5 次命中就 3 杀 | 不报（样本不足） |
| `cheat_aimbot` | 作弊 | 92% 命中 / 93% 爆头 / 83% 远距离爆头 | **报** |
| `cheat_triggerbot` | 作弊 | 95% 命中但爆头率正常 | 不报（单轴弱信号） |
| `cheat_rapidfire` | 作弊 | 峰值 55 发/秒 | **报**（硬违规） |
| `cheat_damage` | 作弊 | 单发 600 伤害 | **报**（硬违规） |
| `cheat_killfarm` | 作弊 | 2 分钟 40 杀 | **报**（硬违规） |
| `cheat_full` | 作弊 | 所有指标一起爆 | **报**（满分） |

### 关于 `cheat_triggerbot` 为什么不报

只有命中率一个信号异常，得分 25 —— 够不到 35 的送审阈值。

**这是设计意图，不是漏报。** 一个 95% 命中率的玩家，和「拿霰弹枪近距离作战」在数值上无法区分。只有这一个信号就惊动 AI，会造成大量无意义的误报。

如果它同时还有任何别的异常（爆头率、射速、伤害），累积分立刻就会越线。

## 它抓出的真实缺陷

这个工具第一次跑就发现了反作弊的 3 个问题 —— 这就是它存在的价值。

### 缺陷 1：评分曲线太软

```
自瞄场景：命中率 91.7%、爆头率 92.7% → 只拿 63.3 分
```

原因是线性映射：`(0.927-0.75)/(1-0.75) = 0.708`，只给了七成分。但 92.7% 的爆头率**应该顶格**。

**修复**：引入**饱和点**概念 —— 75% 是起点，95% 就满格。

**效果**：自瞄场景 63.3 → **73.9**。

### 缺陷 2：单一"物理不可能"信号无法触发上报 ⚠️

```
射速修改（55 发/秒） → 25 分 → 不送审
伤害修改（600 伤害） → 25 分 → 不送审
```

**每根轴最高才 25-30 分，而送审阈值是 35 —— 单轴再离谱也永远报不出来。**

比如单发 600 伤害：**没有任何武器能做到**，这基本等同铁证，却因为"只有一根轴报警"而被忽略。

**修复**：引入**硬违规**机制。超过配置上限若干倍（伤害 3 倍、射速 2 倍、击杀速率 3 倍）视为物理上不可能，**单独一条就强制送审**，不依赖累积分。

**效果**：

```
cheat_rapidfire  21.9 分  送审=是  硬违规=是
cheat_damage     25.0 分  送审=是  硬违规=是
cheat_killfarm   25.0 分  送审=是  硬违规=是
```

有硬违规时，AI 判定后执行动作的门槛也从 80 降到 50（`hard_violation_threshold`）—— 物理上不可能的读数不该被一个犹豫的 AI 挡下来。

### 缺陷 3：模拟器自己的判断和插件不一致

修完硬违规后，模拟器表格里 `cheat_rapidfire` 显示"送审=否"，但插件实际会送审 —— 因为模拟器只用了 `score >= threshold`，没调用新的 `ShouldReport()`。

**修复**：让模拟器复用 `ShouldReport()`，保证测的就是插件跑的那条路径。

## 用模拟器验证 AI

模拟器的另一半价值：**验证 AI 会不会误判**。

```bash
CheatSimulator.exe --ai --key sk-你的key
```

它会逐个场景调用 DeepSeek，然后检查：

- **正常玩家被 AI 判为 ≥80%** → 报"误报" ❌
- **明显作弊被 AI 判为 <30%** → 报"漏报" ❌

这能回答一个关键问题：**你那套阈值设置，AI 会不会把高玩冤枉成作弊？**

建议流程：

1. 先离线跑 `--ai`，看 `legit_veteran`（65% 命中 / 60% 爆头）被判多少
2. 如果 AI 给它打了高分 → 说明提示词或阈值需要调整
3. 本地 Ollama 也能测：`--ai --url http://127.0.0.1:11434/v1 --no-json-format`
   —— 顺便对比一下小模型和大模型的判定质量差距

## 构建

```bash
cd CheatSimulator
dotnet build -c Release
bin\Release\CheatSimulator.exe
```

模拟器**直接链接插件的源文件**（`Config.cs` / `PlayerStats.cs` / `Heuristics.cs` / `DeepSeekClient.cs` / `Scenarios.cs`），不引用编译好的 DLL。

这样保证：**模拟器测的就是插件里跑的那份代码**，不会出现"测的和跑的不一致"。

## 已知局限

- **测不了事件挂钩。** 它验证的是「拿到统计数据之后」的逻辑。`Shot` / `Died` 事件是否被正确触发、`PlayerStats` 是否在真实枪战中正确累加 —— 这些只能在真实服务器上打一局才知道。`dsac stats` 可以看到真实玩家的累计统计，用来做这一步验证。
- **测不了处置动作。** 踢出/封禁的实际效果（消息、时长、封禁列表写入）需要真实玩家才能验证，且模拟场景被设计为永远不会触发处置。
- **场景是人工构造的。** 真实作弊者的行为分布可能和这些档案不同。如果你的服务器遇到了模拟器没覆盖的作弊方式，把特征加进 `Scenarios.All()` 就行。
